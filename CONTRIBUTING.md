# Bijdragen

1. Bespreek grotere wijzigingen eerst in een GitHub Issue.
2. Werk op een korte feature-, fix- of chore-branch; wijzig `main` niet rechtstreeks.
3. Voeg tests toe voor gedrag en vooral voor financiële berekeningen, autorisatie en foutafhandeling.
4. Open een pull request met het template en koppel het aan een Issue met `Closes #...`.
5. Merge alleen wanneer de vereiste checks slagen en de wijziging is beoordeeld.
6. Gebruik uitsluitend synthetische testdata. Commit nooit echte bonnetjes, klantgegevens, secrets of productie-exportbestanden.

Zie [de GitHub-werkwijze](docs/GITHUB_WORKFLOW.md) voor meer informatie.
